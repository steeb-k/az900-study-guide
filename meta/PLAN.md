# AZ-900 study kit — overview

Two repos, one site. The markdown study guide lives here; the practice site and the HTML guide live in the GitHub Pages repo, under
`azure/`. The kit is a port of the Security+ SY0-701 kit (`steeb-k/secplus-study-guide`, `steeb-k.github.io/sec-plus-test/`): the
same app, re-themed and with its own data. The two sites share no code at run time and no storage keys.

## What exists
- **Study guide (this repo, `/home/steeb/az900-study-guide/`)**, public at github.com/steeb-k/az900-study-guide. One markdown file
  per domain plus reference sheets:
  ```
  00-exam-overview.md                 format, domains & weights, question types, scoring, test-day tactics, schedules
  01-cloud-concepts.md                Domain 1 (25–30%) objectives 1.1–1.3
  02-azure-architecture-services.md   Domain 2 (35–40%) objectives 2.1–2.4
  03-azure-management-governance.md   Domain 3 (30–35%) objectives 3.1–3.4
  90-service-picker.md                requirement → service tables, sound-alike services
  91-acronyms.md                      acronym list: Acronym | Expansion | Meaning (also the source of the site's data/acronyms.js)
  92-numbers-and-comparisons.md       redundancy, tiers, hierarchy limits, roles, locks and other countable facts
  STUDY-GUIDE-FULL.md                 GENERATED by meta/build-full.py: everything in one file
  ```
  Style: compact, for a reader who already works in IT. Microsoft does not number its skill groups; this kit numbers them d.n
  (`## 2.3 Describe Azure storage services`) so the quiz can deep-link. Every outline bullet gets a definition framed the way the
  exam tests it; tables for compare/contrast sets; `> **Exam tip:**` callouts for commonly confused pairs; each domain ends with
  "Most-tested distinctions". Each file carries a one-line AI-generated disclaimer that the site build strips.
  Source outline: Microsoft's AZ-900 study guide, skills measured as of July 20, 2026.
- **Hub page (`/home/steeb/steeb-k.github.io/azure/index.html`, https://steeb-k.github.io/azure/)**: one card per Azure exam.
- **Practice site (`/home/steeb/steeb-k.github.io/azure/az-900/`, https://steeb-k.github.io/azure/az-900/)**. Static, no build
  step, no modules, no fetch, no CDN; works from file:// and from Pages.

  js/ui.js              screens, review grid, results, history, settings; the one copy of the guide slug map
  js/app.js             hash router, session lifecycle, timer, resume-on-load, keyboard, ordering swap animation

  Everything the reader sees says "interactive items".

## Exam model
Microsoft AZ-900: 45 minutes, scored 1–1000, pass 700; Microsoft does not publish the question count (commonly about 35–45). No
labs. The site's final exam is 40 items: 4 interactive items first (spread across domains), then 36 MCQs by weight: D1 10, D2 14,
D3 12 (`window.AZ_EXAM`). Scoring: single MCQ 1 point for the right index; multi MCQ 1 point only for the exact set (no partial
credit); interactive item partial credit = correct cells / total cells, counted as one question-equivalent. `pct = points / total`;
`scaled = round(pct * 1000)`; pass = scaled ≥ 700. The scaled number is a straight percentage estimate, not Microsoft's scaling.

## Practice app behavior
- **Routes:** `#/` home · `#/module/:d` module setup · `#/final` final setup · `#/drill` missed drill · `#/quiz` active session ·
  `#/results/:attemptId` · `#/history` · `#/settings`.
- **Home:** three domain cards (name, weight, bank size, last score, readiness badge), Final Exam card, Missed Drill card, footer nav
  History / Settings / All Azure exams / Source, and a "Resume in-progress …" banner while a session exists.
- **Module setup:** count 10 / 25 / 50 / all; mode Practice (instant feedback with explanation after "Check") or Exam (feedback only at
  the end); "Include interactive items for this domain (up to 2)" on by default.
- **Final exam:** always Exam mode; 45:00 countdown top-right with Pause; the timer runs only while the page is visible and not paused
  (accumulated elapsed ms + `runningSince`), unless "Strict timer" is on in Settings; at 0 it auto-submits.
- **Selection:** per-question `seen` counts; draws prefer least-seen questions (random tie-break), then shuffle; option order shuffled per
  presentation, seeded by session id + question id so it is stable on reload; no repeats within a session.
- **Session UI:** counter `Q 12 / 25`, domain + objective tag in Practice mode only (Exam mode hides it like the real test), stem,
  options as large rows (radio or checkbox with a "Choose N" hint), Flag, Prev/Next, Review grid (answered / unanswered / flagged),
  Submit with an unanswered count. Keyboard: 1–6 select, F flag, ←/→ navigate, Enter check/next. Every change persists immediately.
- **Results:** percent, scaled score with pass/fail, per-domain table, weakest objectives, time used, full review with filters
  All / Missed / Flagged, objective links into the guide, "Retry missed", "Back to home".
- **Missed drill:** questions whose most recent result was wrong, filterable by domain, Practice mode; a correct answer removes one.
- **History:** attempts table (newest first); per-domain attempts, best, last-3 average and readiness badge (green when the last 3
  module attempts are all ≥ 80%, yellow when the last one is, red otherwise); final-exam summary. CSS bars, no chart library.
- **Settings:** export JSON, import (merge or replace), reset everything (confirm), strict timer, theme auto / light / dark.
- **Storage keys** (JSON, prefix `az900.`): `version`, `session`, `attempts`, `qstats` ({qid: {seen, correct, wrong, lastCorrect,
  lastAt}}), `settings`; the guide adds `guide.last` and `highlights`. The Security+ site on the same origin uses `secplus.`.

## Specs and tests
- `QUESTION-SCHEMA.md` — bank formats and authoring rules; `DESIGN.md` — tokens, header, components; `GUIDE-SITE.md` — the HTML guide.
- Site tests, all of which must pass: `node tests/validate-bank.js`, `node tests/engine.test.js`, `node tests/guide-core.test.js`,
  `node tests/guide-ui.test.js` (headless Chromium), `bash tests/smoke.sh` for `index.html`, `guide/index.html` and `tests/dev.html`,
  `bash tests/guide-sync.sh`.
- After any markdown edit here: `python3 meta/build-full.py`, `python3 meta/build-site.py`, then the sync and smoke tests in the site,
  then commit both repos.

## Adding another exam
Copy `azure/az-900/` to `azure/<exam>/`, change the storage prefix (`js/storage.js`, the theme snippets, `guide/guide.js`), the data
files, the pill and titles, the slug maps (`js/ui.js`, `meta/build-site.py`), and add a card to `azure/index.html`.
